### T10: Structural misfile: a one-row-per file with a second row for the same key

- **Status:** promising
- **Family:** record_reversal
- **Aimed at:** both
- **Clock trap:** no
- **Aliases:** structural misfile
- **Pooled misses:** Fable 17/55 (31%), Astra 41/55 (75%)
- **Loopholes:** L-record, L-join, L-union

A file holds one row (comment, line) per item and says so; the filed key already has its own row, a second row under that key quotes another item's content, and the true item has no row. The default keeps the second row under its key. Built in the v6/B7 unblock round after Astra missed content-only misfiles; it bit Astra in brightwater 1.5.0 and killzone 1.5.0 and neither model in spice 2.6.0 or line-colour 1.5.0. No audit yet. Measured here (build_evidence.py, 2026-10-15): final 10x2 pooled Fable 12/30, Astra 26/30; all stages Fable 17/55, Astra 41/55 (AMBIGUOUS/DEFECT units excluded); without unaudited >=90% units, final Fable 0/10, Astra 6/10. Audited GENUINE in 0 task(s). Status promising: short of proven: audited GENUINE in 0 task(s) (< 2); no model with pooled final rate >= 0.2 at n >= 20; not dead (some model above 0.05 or n < 20).

**Recipe**

- *record:* a one-row-per-X table with two rows under one key and none under the true item
- *anchors:* the conservation sentence ('one row per page field'), the key's own row, and the stray row's content matching the true item
- *withheld:* no sentence says the row is misfiled
- *dials:*
  - remove the conservation sentence to leave only the content route
  - a quoted title matching the true item word for word is the strongest content route
- *conservation:* the conservation sentence itself; grade the true item's value and the filed key's value
- *shields:* none

**Proof obligations (authoring/validate.py)**

- structure asserted in make_fixture/validate.py: one row per item, two under the filed key, none under the true item
- uniqueness of the content match
- ablation of the quoted content (executed)
- section-14 audit (none yet)

**Hazards**

- unaudited: the brightwater 1.5.0 and killzone 1.5.0 bites have blind readers at most; killzone 1.5.0 reader 0.78 (failed another check)

**What killed it**

- spice 2.6.0 P7 and line-colour 1.5.0 P5: 0/5 on both models in the pilot

**Trace signals**

- the user points out a duplicate row or comment under one item
- SEO tables, comment tools and ledgers with one entry per item

**Domains**

- web content specifications
- trading journals
- deck review tools
- transit design files

**Example.** A metadata table with one description per page has two descriptions under one page; the second repeats another page's copy, and that other page has none.

### T1: Keying slip: a record filed under an ID it does not belong to

- **Status:** proven
- **Family:** record_reversal
- **Aimed at:** both
- **Clock trap:** no
- **Aliases:** ID.slip, keying slip, governing_vs_filing_key
- **Pooled misses:** Fable 742/1835 (40%), Astra 602/1490 (40%)
- **Loopholes:** L-record, L-join, L-union, L-threshold

A structured record (export row, log entry, filed note) carries an ID that is not its owner's. The default joins on the printed key and prices, counts or routes the record under that ID. The files make that impossible: two or more first-hand remarks from different parties describe the record's content, and only the true owner fits. Fable usually notices the conflict and keeps the record anyway; Astra joins silently. Measured here (build_evidence.py, 2026-10-15): final 10x2 pooled Fable 345/680, Astra 321/670; all stages Fable 742/1835, Astra 602/1490 (AMBIGUOUS/DEFECT units excluded); without unaudited >=90% units, final Fable 297/610, Astra 257/580. Audited GENUINE in 13 task(s). Status proven: audited GENUINE in 13 tasks; pooled final miss rate >= 0.2 with n >= 20 on fable, astra (unaudited >= 90% units excluded).

**Recipe**

- *record:* an official-looking keyed record (export row, dispatch line, inbox row) whose own content fits its printed key well enough to pass a casual check
- *anchors:* two or more by-the-way remarks from different parties, each in a document read for another purpose, that describe the record's content and fit only the true owner; at least one makes the printed owner impossible (a date, a location, a transfer)
- *withheld:* no sentence gives the key or record priority, and no sentence names the mechanism of the slip (no 'typo', no 'page-number slip'); the solver supplies the mechanism
- *dials:*
  - one by-the-way anchor per notch toward solvable (a witness of the event or a unique content match)
  - for Astra change the KIND of evidence, not the amount
  - never add a descriptor only the true owner has: it flips the bite to 0
- *conservation:* when the record could be credited to both IDs, grade both sides against a conserved total so the union answer loses
- *shields:* if a tempting rule exists, scope it away from the keyed variable explicitly

**Proof obligations (authoring/validate.py)**

- uniqueness: solve.py enumerates the candidate owners and exactly one fits every anchor
- ablation: dropping each anchor leaves the owner underdetermined or the default (executed)
- no-priority grep: no fixture sentence binds the printed key (audits withdrew psychopathy 2.1.0, ktp 2.1.0, cafe 2.1.0 for one)
- additivity: the keyed reading fails exactly this premise's checks (design_lint)
- blind reader before any dial when a model misses 5/5

**Hazards**

- a sentence that blesses the record makes it AMBIGUOUS: psychopathy 2.1.0 P4 ('the log decides'), ktp 2.1.0 P2 ('the class journal records each lesson'), cafe 2.1.0 P10 (clause 2.2 'drawings govern')
- two records that conflict symmetrically with nothing to decide between them: coloring 2.2.0 P2/P5/P8 AMBIGUOUS, fixed by one first-hand remark in 2.3.0
- a column whose provenance is unstated while a rule defers to it: probation 2.2.0 P4 (AMBIGUOUS, re-audit UNCLEAR)
- a later dated note that supports the printed label: feast 1.1.0 P3 AMBIGUOUS
- a graded label that exists in no file: line-colour 1.0.0 P2 DEFECT
- a 'credit both' reading left open when nothing makes the printed owner impossible: ats 1.1.0 and 1.6.0 P2, closed by an impossibility anchor in 1.7.0
- often flat: 10 of the 19 audited units in the 45-task pass were missed at least 90% by Fable (kibo P3, pathway P2, ats P2, suitcase P5)

**What killed it**

- one descriptor only the true owner has: cnc 2.4.0/2.5.0 P3 'still coiled, wire-tied' took 15/15 to 0/5 on both models
- a specific first-hand noun: coloring 2.4.0/2.5.0 'little crow' took Fable to 2/15, 4/15, 0/15
- a new note placed beside the anchor primes a destination check: gst 1.5.0 P1 11/15 to 0/5 with byte-identical premise text
- one origin remark: gst 1.5.0 P4 'lorry up from Hubballi' 13/15 to 0/5
- kibo 2.8.0 P3 dial (hand-typed name route) overshot to 0/5 on both

**Trace signals**

- the user corrects which file, row, ID or person an item belongs to
- two lists keyed by IDs that are easy to transpose (adjacent register lines, consecutive slide or order numbers)
- a record built by someone other than the people who saw the event (data entry from paper slips, an export of hand-typed names)

**Domains**

- school registers and option slips
- procurement and goods received
- applicant tracking
- production logs and art boards
- small-business bookkeeping

**Example.** An export row keyed to a learner who transferred out three days before slips were collected carries a combination that the homeroom teacher's note and a club leader's remark both tie to a classmate whose slip is missing from the export.

### T5: Misfiled note or record: filed under one item, content only fits another

- **Status:** proven
- **Family:** record_reversal
- **Aimed at:** both
- **Clock trap:** no
- **Aliases:** misfiled note
- **Pooled misses:** Fable 53/170 (31%), Astra 81/170 (48%)
- **Loopholes:** L-record, L-absorb, L-threshold

A note, comment, letter or certificate is filed under item A, but what it says can only be about item B (dates, details or a description that A cannot meet). The default applies it to A as filed. Content-only misfiles bit Astra hard in some builds (ats, pathway) and not at all in others (spice 2.5.0, line-colour 1.4.0, timesheet 2.7.0). Measured here (build_evidence.py, 2026-10-15): final 10x2 pooled Fable 26/80, Astra 41/80; all stages Fable 53/170, Astra 81/170 (AMBIGUOUS/DEFECT units excluded); without unaudited >=90% units, final Fable 26/60, Astra 21/60. Audited GENUINE in 2 task(s). Status proven: audited GENUINE in 2 tasks; pooled final miss rate >= 0.2 with n >= 20 on fable, astra (unaudited >= 90% units excluded).

**Recipe**

- *record:* a complete note or comment that fits its filed key on a casual read
- *anchors:* two near-true details in the note that A cannot meet and B does (a date offset, a prior history), each checked against a record read for another purpose
- *withheld:* no sentence says the note was misfiled
- *dials:*
  - two near-true details: the ats 1.6.0 reader solved it, models still missed
  - an impossibility on A closes the 'apply to both' reading
- *conservation:* grade both A's and B's resulting values so 'apply to both' loses
- *shields:* none needed unless a filing rule exists; then scope it

**Proof obligations (authoring/validate.py)**

- uniqueness: only B meets every detail of the note
- ablation: each detail is necessary
- both-side grading: the union answer fails a check

**Hazards**

- a one-day relayed count plus one likelihood is the thinnest point the audit accepted: ats 1.7.0 P6
- flat when it bites: ats 1.7.0 P6 was 20/20 the same wrong value

**What killed it**

- timesheet 2.7.0 P6 IT-log note: 0/15 on both models
- spice 2.5.0 P7 and line-colour 1.4.0 P5: 0/5 on both

**Trace signals**

- the user says a comment or attachment belongs to another item
- comment exports, certificate logs and correspondence filed by subject line

**Domains**

- recruiting and HR registers
- school administration
- deck and document review
- trading journals
